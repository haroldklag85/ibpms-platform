## 2. Logic Chain

1. **Lombok & MapStruct ordering**: When Lombok runs before MapStruct processor and `lombok-mapstruct-binding` is used, the Java compiler processes Lombok annotations (generating getters, setters, and builders) first. This allows MapStruct to detect these members and compile correct mapping implementations instead of generating empty methods.
2. **Liquibase Schema Initialization**: Setting `spring.liquibase.enabled = true` forces Liquibase to run migration scripts, which creates all necessary tables and immutability triggers (like the append-only event store constraints).
3. **Clean Container State**: Running `docker-compose down` and `docker-compose up` clears pre-existing tables generated by Hibernate, preventing conflicts where Liquibase attempts to create already existing tables. Once the DB state is clean, Liquibase runs successfully and both `FormEventStoreImmutabilityTest` and `TaskDraftIntegrationTest` pass without issue.

## 3. Caveats

- Pre-existing test suite errors in unrelated components (e.g., `DeployRequestWorkflowTest` due to a missing default value for the `is_public` column in raw SQL inserts, or `SlaAdminControllerTest` due to a mockito stubbing error) are present in the full `mvn test` run. These are pre-existing issues not caused by MapStruct/Lombok remediation.

## 4. Conclusion

- Traceability headers were added to line 1 of all 14 target files.
- The target tests (`TaskDraftIntegrationTest` and `FormEventStoreImmutabilityTest`) run and pass successfully in a clean Docker E2E database environment with Liquibase enabled.
