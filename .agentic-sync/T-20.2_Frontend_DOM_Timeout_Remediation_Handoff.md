## 🔬 Diagnóstico del Arquitecto

La auditoría E2E T-20 (Journey J-04) arrojó múltiples fallos de Playwright por `Timeout` (~12 tests) esperando elementos del DOM tras la navegación. Los specs afectados son `phase1-workdesk`, `smoke-j04-operario` y `us002-workbox-kanban`. Esto suele indicar que el DataGrid (y otros componentes Vue) se atascan en estado `isLoading=true` debido a promesas colgantes, dependencias de backend no controladas, o selectores e IDs alterados.

| Violación/Hallazgo | Ubicación | Detalle |
|--------------------|:---------:|---------|
| Timeout renderizado DataGrid | `Workdesk.vue` / `Workbox.vue` | El componente UI no está rindiendo los selectores que espera Playwright. Posible desincronización DOM/Backend o promesas no resueltas. |

---

## 🎯 Instrucciones Quirúrgicas

### Paso 1: Auditoría de Sincronización Asíncrona y Estado `isLoading`

**Archivo:** `frontend/src/views/Workdesk.vue` (o equivalentes que usen el DataGrid)

Debes revisar que el ciclo de vida `onMounted` y los métodos que alimentan los Pinia stores resuelvan limpiamente su estado, garantizando que los elementos de UI no queden eternamente bajo un `v-if="isLoading"`.

```typescript
// Snippet prescriptivo — Asegurar el bloque finally
// @Traceability: US-001, CA-XX (Remediación Timeout DOM J-04)
onMounted(async () => {
  isLoading.value = true;
  try {
    await integrationStore.fetchData();
  } catch (err) {
    console.error("Error cargando DataGrid:", err);
    // Gestionar error (toast o estado vacío) para NO dejar la UI en blanco
  } finally {
    isLoading.value = false; // CRÍTICO: Liberar la UI para el renderizado
  }
});
```

### Paso 2: Verificación de Selectores DOM

Asegúrate de que los componentes tengan aplicados correctamente sus `data-testid` u otros atributos para que Playwright pueda detectarlos sin timeout. Los componentes DataGrid deben instanciarse y mostrar contenido o una variante empty-state clara de forma asíncrona pero sin bloqueos.
